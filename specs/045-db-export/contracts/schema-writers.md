# Contract: Schema writers (`apps/app/src/db/export`)

Pure, synchronous, deterministic. No DOM, no network, no deck writes. Types in
[data-model.md](../data-model.md).

## Entry point

```ts
export function schemaExport(deck: SododeckFile, request: SchemaExportRequest): SchemaExportResult;
export function buildSchemaSlice(deck: SododeckFile, request: SchemaExportRequest): SchemaSlice;
export function availableSchemaScopes(deck: SododeckFile, ui: SchemaScopeUi): SchemaScopes;
export function schemaFileName(
  deck: SododeckFile,
  request: SchemaExportRequest,
  scopeTitle: string | null,
): string;

// per format, all (slice, options) → { text, notes }
export function writeSql(
  slice: SchemaSlice,
  dialect: SqlDialect,
  options: SqlOptions,
): WriterOutput;
export function writeDbml(slice: SchemaSlice): WriterOutput;
export function writeMermaidEr(slice: SchemaSlice): WriterOutput;
export function writeDictionary(slice: SchemaSlice): WriterOutput;
```

**Guarantees (tested):**

- Same input → byte-identical text (FR-013, SC-005); `\n` line ends; one trailing newline.
- Never throws on a schema-valid deck; every skip or change yields an `ExportNote` (SC-006).
- `tableCount === 0` → `text === ''` and the dialog shows the empty state.
- Writers read only the slice; the slice reads only the deck snapshot and the request.

## SQL (`writeSql`)

Statement order:

1. Header comment: `-- <deck> · <scope> · <Dialect>` and `-- Generated by Sododeck. Notes: n`.
2. Postgres `CREATE SCHEMA IF NOT EXISTS` / MySQL `CREATE DATABASE IF NOT EXISTS` per schema used.
3. Postgres enums used by the first table that needs them, just before it (option on).
4. Per table in `sqlOrder` (dependency order): `CREATE TABLE [IF NOT EXISTS] name (` columns, then table-level
   `PRIMARY KEY (…)` when composite, unique / FK / check constraints `);`, then its comments
   (Postgres `COMMENT ON`), then its indexes (option on). Junction tables follow R6 placement with
   a `-- n-n a ↔ b` line.
5. Deferred FKs: `ALTER TABLE t ADD FOREIGN KEY (…) REFERENCES r (…) [ON DELETE …] [ON UPDATE …];`.

Column line: `name type [GENERATED BY DEFAULT AS IDENTITY | AUTO_INCREMENT] [NOT NULL] [UNIQUE]
[DEFAULT …] [CHECK (…)] [PRIMARY KEY (single)] [REFERENCES … (Postgres / SQLite single FK)]
[COMMENT '…' (MySQL)]`. Two-space indent, `,` at line end, keywords upper case, types lower case.
Referential actions map `cascade → CASCADE`, `restrict → RESTRICT`, `set-null → SET NULL`,
`set-default → SET DEFAULT`, `no-action → NO ACTION`; absent → omitted.

Golden example (Postgres, "Shop" excerpt, matching frame 145):

```sql
-- Shop · Orders DB · Postgres
CREATE TYPE order_status AS ENUM ('pending', 'paid', 'shipped', 'cancelled');

CREATE TABLE orders (
  id uuid PRIMARY KEY,
  customer_id uuid NOT NULL REFERENCES customers (id) ON DELETE CASCADE,
  status order_status NOT NULL DEFAULT 'pending',
  created_at timestamptz NOT NULL DEFAULT now()
);

-- n-n products ↔ categories
CREATE TABLE products_categories (
  products_id uuid REFERENCES products (id),
  categories_id uuid REFERENCES categories (id),
  PRIMARY KEY (products_id, categories_id)
);
```

## DBML (`writeDbml`)

Order: optional `Project`, enums, tables (stable `tables` order), refs (relationship order by from table,
then id). Rules in research R14. Example:

```dbml
Enum order_status {
  pending
  paid
}

Table orders {
  id uuid [pk]
  customer_id uuid [not null]
  status order_status [not null, default: 'pending']
  created_at timestamptz [not null, default: `now()`]
  Note: 'One row per checkout'
}

Ref: orders.customer_id ?> customers.id [delete: cascade]
Ref: products.id <> categories.id
```

## Mermaid ER (`writeMermaidEr`)

```text
erDiagram
  customers ||--o{ orders : "customer_id"
  orders {
    uuid id PK
    uuid customer_id FK
    order_status status
  }
```

- Relationship line `A <left><--><right> B : "label"`, where the left mark describes A's side as
  seen from B and the right mark B's side: exactly one `||`, zero or one `|o` / `o|`, one or many
  `}|` / `|{`, zero or many `}o` / `o{`. Label: relationship label, else the FK column list.
- Entities in stable `tables` order, relationships after entities; keys `PK`, `FK`, `UK` (comma list); the
  column note (or the original name / type when changed, R10) as the quoted comment.
- No cardinality → `}o--||` from the FK side and a note.

## Data dictionary (`writeDictionary`)

Layout in research R15. Column table columns: Column, Type, Key (`PK`, `FK → customers.id`, `UQ`),
Null (`yes` / `no`), Default (value quoted / expression in backticks), Note. Generic types
written as stored; dialect in the title only when not Generic.
