## Bugs found

Fixed. Each fix has a failing test first, then app typecheck, lint and the full app test suite
(3,075 tests) passed:

- `cad7a97` fix(app): new bend lands where released on a connector without bends (050 US1).
  `deck-edge.tsx` handed the bend handles the handle points as "card centres" while the connector
  had no bends or pins (`sized` false). The first bend was encoded against the wrong origin, then
  decoded against the real centres, so it moved. This dates from 022 but breaks US1 scenario 2.
  Test: `deck-edge.test.tsx`.
- `3f7cb1d` fix(app): a ⌘ handle drag keeps the connector selected (050 US1). The handle's
  `click` bubbled through the viewport portal to the edge's click handler. There ⌘-click toggles
  the selection, so every ⌘ (no snap) drag of an end, bend, midpoint or segment ended with the
  connector deselected. Test: `route-handles.test.tsx`.
- `c4c4a11` fix(app): dragging the Weight slider no longer selects its stop numbers (050 US3).
  Test: `line-style-popover.test.tsx`.

Not fixed (need a decision):

- **Scenario 14: no group delete confirmation with a connection count.** The contract and the
  quickstart expect one. Today "Delete group" deletes at once (with Undo) and says only
  "Ungrouped …", and Delete on a group is refused. Adding a confirmation, or a count in the
  toast, is a UX choice, so I left it.
- **Scenario 16, `pointercancel` during a card drag.** The guide safety net leaves a running
  gesture alone, and the card drag does not end on `pointercancel`, so the guide stays until
  release. A synthetic event cannot show whether a real browser cancel (touch, or the system
  taking the pointer) leaves a guide behind. Worth a check on a touch device.
- Small things outside 050's scope: group labels read "1 nodes" and merged connectors read
  "1 connections". When drilled in, the "Outside" proxy pill sits partly under the left rail.

## How this was run

- App: `pnpm --filter @sododeck/app dev --port 5199` (dev server, HMR picked up the fixes; the
  final run of every scenario was after all three fixes).
- Driver: Node scripts with the repo's Playwright 1.63 Chromium, in the session scratchpad. No
  test was added to the repo. Each scenario gets a fresh browser context, so IndexedDB starts
  empty. It writes a `.sododeck.json` deck (cards A, B, C, D; group "Data layer" with C and the
  nested group "Cache" with D; extra cards, groups and connectors per scenario) and imports it
  with the library's `import-input`, then opens it.
- Input: real `page.mouse` down / move-in-steps / up and `page.keyboard`, so pointer events,
  thresholds and capture-phase listeners run as for a user. Handles are found by their accessible
  names from the UI contract ("Source end", "Target end", "Add bend between points …",
  "Bend N of M", "Move segment N", slider "Weight", "Connect from {title}", "Spread ends evenly").
- Checks: the document is read back after each step through ⌘K "Export deck" → JSON → Download,
  and compared field by field or byte for byte. Undo uses the History island button. Also checked
  in the DOM: handle positions, `snap-guide` count, `edge-selection-halo`, computed stroke widths,
  readouts (`route-readout` / `endpoint-readout`) and the live region (a MutationObserver on the
  announcer).
- Not reproducible exactly in automation: a release outside the browser window (approximated with
  a CDP release at x = −40), Alt-Tab (simulated with a window `blur` event) and a real
  `pointercancel` (simulated with a synthetic event).
