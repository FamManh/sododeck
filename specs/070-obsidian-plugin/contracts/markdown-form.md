# Contract: the `.sododeck.md` form of a deck

Normative text for `packages/model/src/markdown-form.ts` (plan phase A). Same deck, a second container. The deck JSON inside is the deck format unchanged (ADR 0002, 0020); this document only says how it is wrapped, how its prose is mirrored as readable text, and how edits to that text are read back.

## API (text in, text out; no Yjs, no I/O)

```ts
export const MARKER_KEY = 'sododeck-plugin';
export const MARKER_VALUE = 'parsed';

/** True when text starts with front matter that carries the marker. Cheap; used before any parse. */
export function isDeckMarkdown(text: string): boolean;

/**
 * Wrap canonical deck JSON (what `serializeDeck` returns) as a `.sododeck.md` note.
 * `previous` is the last file text read or written (optional): text outside the owned region and
 * unknown front matter keys are copied from it, and recognised-but-unchanged parts are written
 * byte-identically so an unchanged deck gives an unchanged file.
 */
export function toMarkdown(deckText: string, previous?: string): string;

export type FromMarkdown =
  | { ok: true; deckText: string; edited: boolean } // canonical deck JSON, readable edits applied
  | { ok: false; entries: ProblemEntry[] }; // same entry type the import path uses

/**
 * Read a `.sododeck.md` note back to deck JSON. Lenient about everything except the deck block:
 * it never validates the deck (the editor and `inspectDeckText` do). `edited` is true when at
 * least one title or notes value came from the readable part and differs from the block.
 */
export function fromMarkdown(markdown: string): FromMarkdown;
```

Failure entries (codes added to `problem-codes.ts` with plain messages): `md-no-marker`, `md-no-deck-block`, `md-deck-block-not-json`, `md-two-deck-blocks`. A deck block that parses but is not a valid deck is **not** an `fromMarkdown` failure: its text is returned and the editor shows the deck problems.

## File layout

````text
---
sododeck-plugin: parsed
<any other keys the user or the app added are kept>
---
<user text before the region: kept verbatim>
%% sododeck:begin — generated by Sododeck; edit titles and notes, not the marker comments %%
# <deck name> %%deck%%

%%deck:description%%
<deck description, markdown>

## Components
### <node title> %%<node id>%%

%%<node id>:description%%
<node description, markdown>
…
## Pictures
- [[<link>]] %%<asset id>%%          (picture stored as a vault file)
- <name> %%<asset id>%%               (picture embedded in the deck block)
%% sododeck:data
```json
<canonical deck JSON, indented two spaces, `%%` written as `%%`>
````

%%
%% sododeck:end %%
<user text after the region: kept verbatim>

`````

- The **owned region** is from the `%% sododeck:begin` line to the `%% sododeck:end %%` line. Everything outside it (before and after) is the user's and is copied from `previous`; when there is no `previous`, both are empty. A file with no region is "marker only" (an empty deck, FR-010 of the spec).
- The opening line may carry any text after `sododeck:begin` (a hint for people); the hint must not contain `%%`, which would end the comment early (implementation note, 2026-10-07: the first draft's hint did). Readers match the prefix `%% sododeck:begin`.
- One deck block per file. Two blocks is `md-two-deck-blocks`.

## The readable part

A **marker** is `%%<id>%%` at the end of a heading line (the heading's text is the object's **title**), or `%%<id>:<field>%%` alone on a line (the lines after it are the **body** of that field). Ids are the deck's stable ids (any characters except whitespace, `%` and `:`; flow and step ids such as `flow.a.s1` contain dots; the deck's own `rules` keys too); `deck` stands for the deck itself. A body ends at the next marker line, the next heading line, or the end of the owned region.

| Object | Title (heading) | Body fields (marker `:<field>`) | Notes |
| --- | --- | --- | --- |
| deck (`deck`) | `name` | `description` | H1 |
| `nodes[]` | `title` | `description` | under `## Components` |
| `groups[]` | `title` | `description` | `## Groups` |
| `edges[]` | `label` (may be empty) | `description` | `## Connections`; empty label: heading text `(unnamed)` |
| `features[]` | `title` | `description` | `## Features` |
| `flows[]` | `title` | `description` | `## Flows` |
| `flows[].steps[]` | `title` (optional) | `description`, `notes` | `####`, under its flow; numbering is display-only |
| `rules{}` | `title` | `description` | `## Rules` |
| `stickies[]` | none (heading `Note`) | `text` | `## Notes` |
| `views[]` | `title` | none | `## Views` |

Everything else (positions, sizes, styles, connections, rule tables, tags, fields, links, flows' structure, branches, database parts, images) stays only in the deck block and is never read from the readable part. Which prose fields are listed here comes from the schema's "(markdown)" and `Text` fields (research R6; a schema test keeps the table in sync with `text-fields.ts`: a new prose field is a failing test until the table says what to do).

The `## …` structural headings are cosmetic; objects are found **only by markers**, so the user may reorder, rename or add headings without effect on reading.

## Reading rules (`fromMarkdown`)

1. Find the owned region and the deck block; parse the block as JSON (BOM and line endings tolerated).
2. For each marker with a known id and field, take its value from the readable part: **title** = the heading text with the marker and trailing spaces removed (unescaped, below); **body** = the lines up to the next marker or heading, with the first and last blank lines trimmed (unescaped). If it differs from the block's value, the readable value **wins**.
3. A value that would be invalid in the schema (an empty required title, an empty required sticky text) is ignored: the block's value stays.
4. A marker whose id or field is unknown, or a heading without a marker, is ignored (kept on the next write: see writing rule 3). Deleting a heading or a body never deletes an object or clears a field that is optional in the schema... except a body that is **present and empty** (marker line followed by a blank body), which clears an optional field (sets it absent) because the user deliberately emptied it. A missing marker line changes nothing.
5. Picture list: for each `- [[link]] %%<asset id>%%` whose id exists in `assets`, set that asset's `path` to the link text (without `[[ ]]`, any `|alias` or `#subpath` removed). The link text must pass `checkPicturePath`; otherwise the block's value stays. This is how a move or rename done by the app (which rewrites the visible link) reaches the deck.
6. Return the deck as canonical JSON (`canonicalize`, two-space indent, trailing newline), identical in form to `serializeDeck`.

## Writing rules (`toMarkdown`)

1. Parse `deckText` (canonical JSON). Generate the owned region in the fixed order above (objects in the deck's own array order, rules in map order).
2. Emit each title and body through the escaping rules below. An optional prose field that is absent writes **no** marker line (a field that is `""` writes an empty body, so reading restores it).
3. With `previous`: keep front matter keys other than the marker, keep text before `begin` and after `end` verbatim, and re-attach **foreign blocks** (headings or text inside the old region that no marker explains) after the marked item they followed; a foreign block that followed no marked item stays at the top of the region.
4. Picture list: an asset with `path` writes `- [[<path>]] %%<id>%%`; one with `data` writes `- <name> %%<id>%%`. The block still holds each asset's `path` or `data` as in the deck.
5. Deterministic: same input gives the same bytes; with `previous` equal to a file this function wrote from the same deck, the output equals `previous` (no diff).

## Escaping

| Where | Text | Written as | Why |
| --- | --- | --- | --- |
| title or body | `%%` | `%&#37;` | a literal `%%` would open or close a comment |
| body line starting with `#` (after optional spaces) | `# x` | `\# x` | it would read as a heading and cut the body |
| body line equal to `%% sododeck:end %%`-like or starting with `%% sododeck:` | | prefixed with `\` | would end the region |
| title | line break | `<br>` | a heading is one line |
| title | trailing `%%…%%` look-alike | covered by the `%%` rule | |
| deck block | `%%` | `%%` | valid JSON escape, so `JSON.parse` restores it |
| deck block | the fence ```` ``` ```` | not needed: JSON strings escape backticks only by choice, so the writer uses a fence one backtick longer than the longest run in the text | a longer fence cannot be closed by the content |

Reading reverses each rule exactly. Property tested: for any title or body string `s` built from letters, spaces, `%`, `#`, `\`, backticks, `<br>`, `&#37;`, newlines (bodies), unicode, `fromMarkdown(toMarkdown(deckWith(s)))` returns `s`.

## Invariants (tested)

- **Lossless**: `fromMarkdown(toMarkdown(t)).deckText` equals `t` for every sample deck and the test corpus (SC-005).
- **Stable**: `toMarkdown(t, toMarkdown(t))` equals `toMarkdown(t)`.
- **Hand edit by id**: changing a title or body in the readable part changes exactly that field in `deckText`, nothing else (property over all kinds in the table).
- **User text kept**: text before and after the region, extra front matter keys and foreign blocks survive any number of write/read cycles.
- **Ids never change**: no read or write changes, removes or adds an id; unknown markers add nothing.
- **Degrades to a note**: with the plugin removed, the file is a readable Markdown note whose deck block is still ordinary deck JSON (copy it out and it is a `.sododeck`).
- **Size**: conversion of the 500-node bench deck ≤ 50 ms each way.

## Compatibility

- The marker value `parsed` and the region delimiters are part of the format; changing them needs a new marker value and a reader for the old one (ADR 0051).
- `packages/schema` is not touched; the deck block is validated by the existing rules. A deck with `version` above the supported one is refused by the existing newer-version check, not by this module.
