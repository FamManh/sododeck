## Rules (in addition to the root CLAUDE.md)

- Document data lives only in the Yjs doc. Components read a `SododeckFile` snapshot from `useDeckSnapshot(doc)` and write only through `useEditor()` (the `DeckEditor`). Never copy document data into Zustand, React state or React Flow state.
- The canvas is controlled and derived (ADR 0006): `nodes`/`edges` come from the snapshot every render; React Flow never owns document state. Drags write positions to the document inside an editor gesture (one undo step).
- Canvas recipes (new node/edge types, visual modes, zoom levels, viewport) are in the project skill `.agents/skills/react-flow/SKILL.md`. Update it when a file, helper or pattern it names changes.
- No React Flow built-in delete or keyboard handling (`deleteKeyCode={null}`, `disableKeyboardA11y`, nodes/edges not focusable). Keys live in `src/editor/use-canvas-shortcuts.ts`; deletes go through the confirmation dialog, whose counts come from `previewRemoval`. Sticky-note shortcuts live there too: `N` adds a note, `⌥C` collapses / expands the selected note, and ⌘K / Ctrl+K opens the command palette.
- Zustand is for UI state only. If it would be saved in the `.sododeck.json` file, it doesn't belong in Zustand. Drill frames, focus mode, merged-edge popovers, semantic zoom and the current view never write to the deck or the undo history (collapsed groups are view data since 011).
- Visible canvas objects come from `visibleGraph(view.deck, scopeOf(ui.drill), view.collapsed)`, then `toFlowNodes` / `toFlowEdges` (with `view.render`), where `view = useViewState()` / `readViewState(doc)`. Do not filter React Flow objects ad hoc in components or handlers; change the derivation instead.
- Saved views (011, ADR 0012): the current view is tab-local UI state (`ui.currentViewId`, `null` = first view; `switchView`), never written. Everything else about views is document data written only through the model's view ops (`moveInView`, `setPinned`, `updateView`, `addView`, `removeView`, `setCollapsed`); never `update('views', …)`. Canvas geometry reads the view-projected deck (`ViewState.deck`: view positions, hidden components left out); the JSON panel, inspector and outline read the real snapshot. Drags go through `moveInView` (base view → base positions); pinned-note drags through `moveStickyInView`. Collapse is document data per view (`useCollapsed`, `setGroupCollapsed`), saved and synced but never an undo step. Tidy layout runs in the layout worker and applies one `moveInView` batch.
- Flows (006, `src/editor/flows/`): the shown flow (`activeFlow`) and the recording/edit session (`flowSession`) are UI state holding ids only. Steps and branches are written to the deck as they are clicked (`flow-session.ts` → `appendStep`/`addBranch`), so autosave, tab sync and undo need nothing flow-specific. The one exception is the edit-mode Cancel checkpoint (`captureFlowStructure`), opaque and never rendered (ADR 0008). Paths, numbers and from/to always come from `analyzeFlow`; never store or recompute them.
- During a session canvas structure editing is paused (no drags, connects, drops, C, E, Delete); edge clicks record steps (`use-canvas-handlers.ts`), and Tab / Enter cycle and record candidate edges (`use-canvas-shortcuts.ts`). Flow marks reach the canvas only through the optional `overlay` argument of `toFlowEdges` / `toFlowNodes`.
- Flow mode (007) is derived, never stored: `isFlowMode(state)` = `activeFlow !== null && flowSession === null`. `activeFlow` holds ids and playback UI state only (`stepId`, `alternativeId`, `playing`, `speed`). Open and leave it only through `flows/flow-mode.ts` (`openFlow(editor, flowId, stepId?)`, `exitFlow()`, `goToStep`, `nextStep`, `previousStep`, `switchAlternative`, `play`, `advancePlayback`), which resolve steps from `analyzeFlow` and announce each step change exactly once. The played path (main + chosen alternative), the player view, click-to-step and step re-homing are pure functions in `flows/played-path.ts`.
- In flow mode the canvas is view-only: the wrapper gets `data-flow-mode`, CSS dims everything without `.in-flow` and hides handles (`visibility`, never `display: none`, which breaks edge drawing). Sticky notes derive their own flow state in `editor/stickies/sticky-flow.ts`: the current-step notes or `showInFlows` notes stay full strength, other notes dim to 35% or hide based on `ui.notesDisplay`, and note creation / editing is refused until flow mode ends. Drags, drops, connects, reconnects and popovers are refused in `use-canvas-handlers.ts`, not by toggling `nodesDraggable` & co (that re-renders every node and edge). Node/edge clicks jump to a step; canvas keys are off except zoom. Playback keys (← → ↓ ↑) live in `usePlaybackShortcuts` (`flows/use-flow-shortcuts.ts`); Esc exits. Autoplay is one `setTimeout(stepMs / speed)` in `use-playback.ts`, paused on a hidden tab. The current edge's token is `editor/flow-token.tsx`.
- The deck route has one child (008): `rules/:ruleId?` (lazy). `routes/editor-page.tsx`'s `EditorChrome` keeps the doc, delete dialog, live region, command palette, `useEditorShortcuts` and `useFlowSync` for both screens and renders the rule editor under its `TopBar`, or `CanvasScreen` (no top bar) when no child matches. ⌘Z / ⇧⌘Z / ⌘S work on both screens; Delete and Esc (canvas selection) only on the canvas (`useEditorShortcuts({ canvas })`). The canvas viewport is kept in `ui.canvasViewport` and restored on return.
- Inspector text fields save while typing through `useLiveField` (a gesture per focus session: one ⌘Z undoes the field). Discrete edits (tags, links, picks) use `oneStep`. Rule test values (`ui.ruleTest`) are UI-only; only "Save as step inputs" writes them. Rule attach / detach / sample inputs go through the model's `attachRule` / `detachRule` / `setRuleInputs`.
- Deletes of features, flows, branches and rules go through `ui.requestRemoval(targets)` and the same confirmation dialog as the canvas (`pendingDelete.targets` are `RemovalTarget`s). Removing a step inside a session asks nothing (⌘Z restores it).
- The JSON panel (004) only reads: `useDeckSnapshot` → text from `@sododeck/model` (`serializeDeck` for Deck, `serializeEntry`/`serializeEntries` for Selection) → Monaco. Never `JSON.stringify` deck data in the app. Its only writes are `editor.undo()`/`redo()` (⌘Z / ⇧⌘Z / Ctrl+Y inside the viewer). Deck text is throttled to 250 ms and computed only while its tab is visible (`use-throttled-deck-text.ts`).
- JSON viewer (`json-viewer.tsx`): one Monaco model per tab (`DECK_MODEL_PATH`, `SELECTION_MODEL_PATH`; the latter must not match the schema's `*.sododeck.json`). `defaultValue` only seeds a new model; later text goes in as one minimal `applyEdits` from `lineDiff`, never `value`/`setValue` (they reset folds and scroll). `readOnly` + `readOnlyMessage`, no `domReadOnly` (it blocks the read-only hint and event). Themes `sododeck-light`/`-dark` are built from CSS tokens (`monaco-theme.ts`, contrast-tested) and rebuilt when the app theme changes.
- JSON panel preferences `{ open, height, tab }` (open = expanded vs collapsed bar) live in the UI store (`jsonPanel`) and in `localStorage["sododeck.jsonPanel"]` (`state/json-panel-prefs.ts`). The app never switches the tab by itself. Whether the JSON overlay is shown at all is `ui.jsonShown` (⌘J, hidden by default), a per-deck shell preference.
- Monaco is bundled locally via deep imports in `src/editor/monaco-setup.ts`. Never use the CDN loader. Re-check the deep import paths when upgrading `monaco-editor`.
- Heavy modules (React Flow canvas, Monaco, telemetry SDKs) are code-split. Keep the library route light: nothing under `src/library/` or `routes/library-page.tsx` may import `yjs`, `@sododeck/model` or React Flow (check the entry chunk after `pnpm build`). Deck-content work from the library goes through the library worker.
- Deck content is stored only as Yjs updates in the `updates` table. A library record's `name`, counts and `thumb` are caches written from the document with each update (same transaction); never read them back into a document. Only updates with this tab's own origins are persisted or relayed (`storage/origins.ts`).
- Telemetry must never include diagram content: no autocapture, no session replay, no UI/console breadcrumbs, no document data in error messages or event properties.
- The e2e test `makes no third-party network requests` guards rule 5. Don't weaken it; if telemetry is enabled in a test, assert its requests carry no content.
- Problems (015, ADR 0013) are derived, never stored: `useProblems()` reads the per-deck problems store that `ProblemsProvider` (in `EditorShell`) keeps from the problems worker. Never put problems in Zustand (only `ui.problemCursor`, the last visited key), the deck or the JSON panel. Canvas glyphs reach React Flow through `CanvasView.problems` (`problemMarks`), which is part of the node/edge cache check. ⌘. / ⇧⌘. walk the problems via `useEditorShortcuts({ onProblem })`. The only main-thread `checkDeck` call is the before/after count of a confirmed delete (Undo toast "n new problems").
- Canvas-first shell (018, ADR 0014): the canvas never shares its box; all chrome lives in `CanvasShell`'s overlay layer (`pointer-events: none`, each island / flyout / drawer opts back in). Shell state is UI-only in the store (`flyout`, `pinnedFlyout`, `drawer`, `jsonShown`, `hideUi`, `minimap`, `tool`, `helpOpen`); drawer width, pinned flyout and `jsonShown` are also saved per deck in `localStorage["sododeck.shell.<deckId>"]` (`shell-prefs.ts`), read once on open (`resetForDeck(deckId)`), never synced, removed by `purgeDeleted`. Never put shell state in Yjs.
- The details drawer opens only on request (Enter on a plain component, double-click, ⌘⇧D, "Open details", Deck settings) and closes itself when its selection mode has nothing to show (`hasDetailsTarget`). Delete / Esc inside the drawer, a flyout or the JSON overlay never act on the canvas selection (`inOverlay` in `use-canvas-shortcuts.ts`).
- Keys: canvas keys stay in `use-canvas-shortcuts.ts`; shell keys (F6 regions, ⌘\\, ⌘J, ⌘⇧D, ⌥1 / ⌥2, ⇧1 / ⇧2, M, ?, V / S / L tools, C palette with no card focused, 1–6 in the palette) in `shell/use-shell-shortcuts.ts`. Layout-dependent keys read `event.code`. Every user-visible shortcut label comes from `shell/shortcuts.ts`. Regions carry `data-region`; the canvas wrapper is `canvas`.
- Export (012, ADR 0016) only reads: the deck through `useDeckSnapshot`, scope values from the UI store; nothing is written to the deck or the undo history. Images come from `export/scene.ts`, which reuses the pure canvas helpers and must never call `toFlowNodes` / `toFlowEdges` (their single-slot caches serve React Flow). The tools island "Export", the deck menu "Export…" and ⌘K "Export deck…" open the dialog (`openExport(returnFocus)`); the autosave error, deck inspector STORAGE and library menu keep the direct backup (`useExportDeck()` / `exportDeckFile`). Files are saved with `storage/download.ts` (`downloadText`, `downloadBlob`); fonts are embedded from `@sododeck/ui/lib/embedded-fonts`, never fetched.
- Anything browser-specific goes through `src/lib/features.ts`.
- The `/design` gallery is registered only when `import.meta.env.DEV`; keep its code and CSS inside `src/design-gallery/` so production builds never include it (check: `grep -r design-gallery dist` finds nothing).
