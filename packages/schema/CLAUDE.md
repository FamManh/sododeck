# @sododeck/schema

**Responsibility:** defines the `.sododeck.json` file format. Nothing else.

- `schema/v1.json` — JSON Schema (draft 2020-12). **The source of truth.** Edit this file, never the generated code.
- `src/generated/` — TS types (`json-schema-to-typescript`) and Zod validators (`json-schema-to-zod`), produced by `pnpm schema:generate`. Committed. `pnpm test` fails if they are stale.
- `src/index.ts` — public API: types, `sododeckFileSchema`, `parseSododeckFile()`, `checkSemanticRules()`, `Issue`, `emptySododeckFile()`, `jsonSchema`, `SCHEMA_URL`; since 062 also the issue codes, `toPointer` / `fromPointer` / `comparePointers` and `toIssues` / `evidenceOf` / `valueAt` / `subjectAt`.
- `src/issue-codes.ts` (062, ADR 0039) — the codes this package emits: `SCHEMA_ISSUE_CODES` (generic `schema-*`, one per violation type), `FORMAT_RULE_CODES` (one per rule S1–S15, I1, I3–I6, e.g. `rule-row-cells`, `image-id-clash`) and `LOAD_ISSUE_CODES` (`duplicate-id`, `ambiguous-end`, emitted by `@sododeck/model`, listed here so `Issue` stays one type). Codes are public and never change meaning; the catalogue with fix hints is `@sododeck/model`'s `problem-codes.ts`.
- `src/pointer.ts` (062) — RFC 6901 JSON Pointers for every issue path (`/flows/0/steps/2/edge`, root `""`); `comparePointers` orders by position in the file (top-level keys in v1.json order, indexes numerically).
- `src/zod-issues.ts` (062) — `toIssues(zodError, input)`: Zod issues → coded `Issue`s with a pointer path, the subject id (nearest enclosing `id`, or the `rules` / `assets` key), evidence (≤ 200 characters) and a fix composed from the violation (expected type, allowed values capped at 12, bounds, id pattern in words). A missing key is always `schema-required`; an unknown key is one issue per key at the key; a union nothing matched reports the closest branch that got past the value's own type, else `schema-union`; a `uniqueItems` duplicate points at the repeated item.
- `src/semantic-rules.ts` — rules the generated Zod cannot check: S1 decision-table rows have one cell per column, S2 a sticky has a position (or the deprecated `anchor`, ADR 0041), S3 map keys are ids, S4 a group has both `position` and `size` or neither (016), S5 `view.groupFrames` keys are group ids of the file (016), S6 style has a colour, S7 edge style has a key, S8 `tagColors` keys (033: non-empty, none equal after trim, space-collapse and lower-casing; the key rule is inlined because this package imports neither model nor ui), S9–S11 connector routes (022), S12 field definitions and S13 card values (032), S14 a table column holds at most one of `default` / `defaultExpr` (040), S15 a step touches each `(table, column)` pair at most once (049), I1 to I6 images (055: asset resolves, key is a 64-hex picture id, `data` decodes to `bytes`, group resolves, id does not clash with a card, group or sticky, size at least 32 px; I7, the hash check, lives in `@sododeck/model` because it needs SHA-256). `parseSododeckFile()` runs them after Zod; Ajv users call `checkSemanticRules()` themselves.
- `examples/` — `minimal`, `flow-and-rule`, `full` (uses every field and enum value; a coverage test enforces it).
- `test/` — Ajv/Zod parity over examples, invalid fixtures and valid edge-case fixtures (`fixtures.ts`, `validFixtures` since 042), lossless parse, key order, generator guards.

## Issues (062, ADR 0039)

`Issue` is `{ code, path, message, subject?, evidence?, fix? }`. `path` is a JSON Pointer (was a dot path before 062). `parseSododeckFile` runs Zod and stops on structural issues; `checkSemanticRules` tags every push with its rule code, the pointer and the object's id, messages unchanged. Tests: `invalidFixtures` carry `{ path (dot form, turned into a pointer by the test), code }`; `zod-issues.test.ts` covers each violation type.

## Boundaries

- No Yjs, no React, no browser APIs. Pure data definitions + validation.
- Does not know about referential integrity (edge → node ids); that is `@sododeck/model`.
- Local `$ref`s only (`#/$defs/...`), and no recursive refs: the Zod generator needs them inlined.
- Field decisions (enums, positions, decision tables, ids): ADR 0004.

## Editing `v1.json`

- Declaration order of `properties` = the key order files are written in. Tests check examples against it.
- Every property gets a `description` (Monaco hover help).
- No `default` (Zod would inject values and break the lossless round-trip) and no `format` keyword. State defaults in the description.
- The generator strips `anyOf` presence rules (both generators mishandle them) and keys next to `$ref` (they make json-schema-to-typescript emit `Id1`, `Text2`… aliases). `propertyNames` is ignored by the Zod generator. Anything the generators drop must be re-checked in `semantic-rules.ts` and covered by an invalid fixture.
- New field or type → extend `examples/full.sododeck.json` (coverage test), add invalid fixtures, run `pnpm schema:generate`, and add a round-trip case in `packages/model/test`.

## Status

v1 complete (feature 001). 006 added flow branches as optional, additive fields with no version bump: `Flow.branches[]` (`Branch { id, label, condition, errorPath?, description? }`) and `Step.branch` (ADR 0008). Empty branch labels and conditions are valid in the file; the editor's Done enforces them.

009 adds two optional sticky booleans with no version bump:

- `Sticky.collapsed?: boolean` — `true` means the note is shown as one line; the editor writes `true` or removes the key.
- `Sticky.showInFlows?: boolean` — `true` keeps the note at full strength during flow playback; the editor writes `true` or removes the key.

Keep the sticky property order `id, text, color, anchor, position, collapsed, showInFlows, size, fontSize, align, tags, locked`. `anchor` is deprecated (ADR 0041: notes are no longer pinned; `@sododeck/model` turns it into a position on load); the full example no longer uses it and `test/coverage.test.ts` lists it in `DEPRECATED`, while `fixtures.ts` keeps valid legacy files. Extend `examples/full.sododeck.json`, and cover invalid non-boolean values in fixtures when these fields change.

053 adds sticky notes as connector ends and richer notes, additive with no version bump (ADR 0031 precedent): `Edge.from` / `to` may name a sticky (descriptions only), optional `Sticky.size` (`$defs/Size`), `fontSize` (integer enum 12, 14, 16, 20, 24, 32; absent = Auto), `align` (`left`, `center`, `right`; absent = centre), `tags` (`$defs/Tags`), `locked` (`const: true`, as 043), appended after `showInFlows` in that order, and optional `Edge.locked` (`const: true`, last key). Invalid fixtures cover bad values. An id shared by a node, a group and a sticky that a connector names is refused by `@sododeck/model` at load (as 050), not here. An older build shows a connector ending on a sticky as a broken reference.

016 adds group frames with no version bump (ADR 0017): `$defs/Size` `{ width, height }` (both > 0; 017 reuses it for `node.size`), `$defs/Frame` `{ position, size }`, optional `Group.position` / `Group.size` (after `parent`, set together: `dependentRequired` in v1.json, S4 in `semantic-rules.ts`) and optional `View.groupFrames` (group id → `Frame`, after `positions`; S5). Per-object validation in `@sododeck/model` runs S4 on groups and supplies the named groups for S5 on a single view.

011 adds optional view fields with no version bump (ADR 0012): `View.excludeGroups`, `excludeKinds`, `excludeTags`, `dimKinds`, `pinned`, `collapsed` (unique lists; absent when empty), and `SubtitleField` gains `flows` ("<n> flows · <owner>"). The example `full.sododeck.json` uses all of them; invalid fixtures cover unknown kinds, duplicates and bad ids.

017 adds optional card size and connector routing with no version bump: `$defs/Side` (`'top' | 'right' | 'bottom' | 'left'`), `Node.size?: Size` (reuses 016's `Size`, after `group`; a stored override of the level's default card size, in canvas px), and `Edge.route?: EdgeRoute` (`{ fromSide?, toSide?, offset? }`, after `links`; pins an end's side and/or shifts the middle segment, all optional, empty object valid). Absent `size` / `route` means "automatic" (today's behaviour unchanged, so old files are byte-identical on round-trip). `examples/full.sododeck.json` sets both; invalid fixtures cover a non-positive `size`, an unknown `Side`, and an `EdgeRoute` with an unknown key.

020 adds card colours with no version bump (ADR 0018): `$defs/CardColor` (13-name enum), `$defs/HexColor` (`^#[0-9a-f]{6}$`), `$defs/ColorRef` (`anyOf [CardColor, HexColor]`; generates a `z.union`), `$defs/Style` (`{ fill?, stroke? }`, `additionalProperties: false`, `minProperties: 1`), optional `Node.style` (after `position`), optional `Group.style` (after `size`), and root `swatches` (`HexColor[]`, `uniqueItems`, no `maxItems` — the 12 cap is a model-only rule, after `tags`). `minProperties` is dropped by json-schema-to-zod, so **S6** ("style has a fill, a stroke, or both") lives in `semantic-rules.ts`; `uniqueItems` survives as a Zod `.refine`. `test/schema-walk.ts`'s `walk()` now follows `anyOf` branches (picking the one whose `enum` or `pattern` matches the value) for leaf unions like `ColorRef`, but skips that path when the schema also has `properties` (e.g. `Sticky`'s presence rule), so object coverage still works.

029 adds the connector line type with no version bump (ADR 0022): `$defs/EdgeShape` (`curved` | `elbow` | `straight`), `$defs/EdgeStyle` (`{ shape? }`, `additionalProperties: false`, `minProperties: 1`) and optional `Edge.style` (after `route`). Absent `shape` reads as `elbow` when `route.offset` is set, else `curved` (computed by `@sododeck/model` `edgeShape`). `minProperties` is dropped by json-schema-to-zod, so **S7** ("edge style has a key") lives in `semantic-rules.ts`. `full.sododeck.json` uses every shape; invalid fixtures cover an unknown shape, an empty style and an unknown key.

033 adds the root `tagColors` with no version bump (ADR 0022): tag text → `ColorRef` (`additionalProperties: { $ref: ColorRef }`), declared right after `swatches`. A tag with no entry is slate. **S8** lives in `semantic-rules.ts` (empty key, keys equal ignoring case and spacing; the path is `tagColors.<key>`). `full.sododeck.json` holds a named and a hex entry, in the sorted order the app writes; invalid fixtures cover an empty key, spaces only, case-duplicates, a bad colour and an array.

030 adds card types and packs with no version bump (ADR 0025): `$defs/NodeKind` is gone; `$defs/TypeId` and `$defs/PackId` (both `^[a-z][a-z0-9-]{0,47}$`) type `node.type`, `view.excludeKinds`, `view.dimKinds` and the new optional root `packs` (`PackId[]`, unique, `minItems: 1`, right after `tagColors`; absent means `["architecture"]`). Unknown ids are valid (the model reports them). The generator passes `ignoreMinAndMaxItems` so `minItems` does not turn `packs` into a non-empty tuple type the Zod output cannot satisfy. `full.sododeck.json` sets `packs` and a `warehouse` card; invalid fixtures cover uppercase, empty, spaced and 49-character ids and empty or duplicate `packs`.
022 adds connector style, anchors, bends and label position with no version bump (ADR 0024): `EdgeStyle` gains `dash`, `width` (enum 1, 1.5, 2, 3, 4), `color` (`ColorRef`), `animated`; `EdgeRoute` gains `fromAt`, `toAt` (0 to 1) and `waypoints` (new `$defs/RouteWaypoint`: one of `x` / `dx` and one of `y` / `dy`, relative to the two card centres); `Edge.labelAt` (0 to 1, after `label`). Rules in `semantic-rules.ts`: **S9** `fromAt` / `toAt` need `fromSide` / `toSide`, **S10** a route never holds both `offset` and `waypoints`, **S11** `waypoints` is not empty and each waypoint has exactly one key per axis (`minItems` would make json-schema-to-typescript emit a tuple type, and `oneOf` is mishandled by the generators). `full.sododeck.json` uses every new key; invalid fixtures cover each rule.

032 adds typed fields with no version bump (ADR 0027, refining ADR 0022): `$defs/FieldKind` (nine kinds), `$defs/StatusIcon`, `$defs/FieldOption` `{ id, label, color?, icon? }`, `$defs/FieldDef` `{ id, name, kind, types?, onCard?, unit?, options? }`, `$defs/DateRangeValue` `{ from, to }`, `$defs/LinkValue` `{ url, label? }` and `$defs/FieldValue` (`anyOf` string, number, date range, link). Root `fields` (`FieldDef[]`) and `fieldDefaults` (`TypeId[]`, unique) follow `packs`; `Node.values` (field id → `FieldValue`) follows `host`. **S12** (field ids unique; built-ins `tech` / `host` / `owner` keep kinds `text` / `text` / `person`; `unit` only on number; `options` only on select / status; option ids unique per field; `icon` only on status options) and **S13** (`values` keys are ids and never a built-in id) live in `semantic-rules.ts`. Values that point at no field or option, or do not fit their field, are valid (the model reports them). `test/schema-walk.ts` `walk()` also follows `anyOf` branches by plain `type` and by an object's known and required keys. `full.sododeck.json` holds a materialised Warehouse field set, every kind, every status icon and every value shape.

040 adds the database schema with no version bump (ADR 0029): `$defs/Dialect`, `DbName` (1–128 characters, one line), `DbExpr`, `DbNote` (plain text, not markdown), `DbAction`, `Cardinality`, `DbDetail`, `ColumnIdList` (`minItems: 1`, unique), `DbColumn`, `DbIndexPart` (`anyOf` column id or `{ expr }`), `DbIndex`, `DbCheck`, `DbEnumValue`, `DbEnum`. Root `dialect` and `enums` follow `fieldDefaults`; `Node` gains `schema`, `columns`, `indexes`, `checks`, `expanded`, `detail` after `style`; `Edge` gains `fromColumns`, `toColumns`, `cardinality`, `fromOptional`, `toOptional`, `onDelete`, `onUpdate` after `style`. `db-table` joins the built-in type ids and `database` the pack ids. json-schema-to-zod keeps `minItems` here (`.min(1)`), so no S15 was needed; **S14** (`default` xor `defaultExpr`, path `nodes.<i>.columns.<j>.defaultExpr`) lives in `semantic-rules.ts`. `full.sododeck.json` holds the "Shop" fragment (tables 12–15 under a `database` card, relationships 7–11, one enum); `Dialect` is the one enum a file can hold only once, so the coverage test expects one value and `schema.test.ts` accepts the others. Fifteen invalid fixtures cover the new shapes.

041 adds two optional keys, no version bump (ADR 0030): `$defs/TableDisplay` (`detail` as `DbDetail`, `hideTypes`, `hideNullable`, `hideNotes`, `hideIndexes`; `additionalProperties: false`) as root `tableDisplay` after `enums`, and `DbEnum.color` (`ColorRef`) after `note`. `full.sododeck.json` gains a second enum (hex colour), a palette colour on the first and a `tableDisplay` with every key; four invalid fixtures cover them.

050 widens connector ends with no shape change and no version bump (ADR 0031): `Edge.from` / `Edge.to` may name a node or a group (descriptions of root `edges`, `Edge`, `from`, `to`, `EdgeRoute` and `RouteWaypoint` say so; route sides and bends read against the group frame). Resolving ends and the node / group id collision check are `@sododeck/model`'s job. `full.sododeck.json` holds a group → card edge (`e-clients-platform`); `test/fixtures.ts` `validFixtures` holds card → group, group → card and group → group.

042 adds one optional key, no version bump: `$defs/RelationshipDisplay` (`hideEnds` boolean, `labels` enum `hover` / `always` / `off`, `notation` enum `numeric`; `additionalProperties: false`, no defaults) as root `relationshipDisplay` after `tableDisplay`. Absent keys mean cardinality ends shown, labels following the Labels tool, crow's foot. `full.sododeck.json` sets every key; four invalid fixtures (bad `labels`, `notation: "crow"`, non-boolean `hideEnds`, unknown key) and two valid ones (empty object, every key) cover it.

043 adds one optional key, no version bump: `Node.locked` (`const: true`, after `detail`) on any node type. Absent means unlocked; `false` is invalid, so unlocking removes the key. `full.sododeck.json` locks one card; invalid fixtures cover `false` and `"yes"`, valid ones a locked card, shape and table.

049 adds one optional, additive field with no version bump (ADR 0035): `Step.touches` (declared last on `Step`), a list of `$defs/Touch` `{ table, column?, access: 'read' | 'write' }`. Duplicate `(table, column)` pairs are S15; whether `table` is a table node and owns `column` is referential integrity (`@sododeck/model`). `examples/full` step `p2` carries table and column touches; fixtures cover a missing `table`, a bad `access`, an unknown key and a duplicate pair.

048 adds three optional keys, no version bump (ADR 0034): root `groupingMode` (`"schema"` only; By group is the absent key) after `relationshipDisplay`, `View.schemas` (`DbName[]`, `minItems: 1`) after `includes`, and `View.detail` (`DbDetail`) after `collapsed`. `view.collapsed` may also hold derived schema group ids (`schema:<name>`); stored group ids never start with `schema:` (a model check). `full.sododeck.json` sets all three on the Custom view; seven invalid fixtures (a mode other than `schema`, a non-string mode, empty / blank / non-list `schemas`, `detail: "auto"`, a non-string `detail`) and four valid ones cover them. A build from before 048 rejects these keys through `additionalProperties: false`.

052 adds one optional key, no version bump (ADR 0029 amendment): root `blockSqlExport` (`const: true`, after `dialect`). Absent means off; `false` is invalid, so turning it off removes the key. `full.sododeck.json` sets it; invalid fixtures cover `false` and `"yes"`, a valid one `true`.

055 adds pictures with no version bump (ADR 0037): root `images` (`$defs/Image`: `id, asset, position, size, z, group, alt, caption, locked`) and `assets` (map of picture id → `$defs/Asset`: `type, bytes, width, height, name, data`), both after `stickies` and written only when non-empty; optional `Node.z` (last key); `Edge.from` / `to` may name an image (descriptions only). `AssetType` is the six-type allow-list (png, jpeg, webp, gif, svg+xml, avif); `bytes` is capped at 5 242 880 by `maximum`; `data` is base64 (`pattern`). Image and node `z` share one stacking order (a higher rank draws on top; absent means the array index). The image `size` reuses `$defs/Size` (`width` / `height`), so the 32 px minimum is rule I6. An entry in `assets` that no image uses is valid (I2) and dropped by the next save. A connector end that names a missing image, and a hash that does not match the key, are `@sododeck/model`'s checks. `full.sododeck.json` holds one image of each of the six types (tiny files) and `order-svc` has `z`.

057 adds image crop and flip with no version bump (ADR 0037 addendum): optional `Image.crop` (`$defs/Crop`: `x`, `y` in [0, 1), `width`, `height` in (0, 1], fractions of the picture's natural size in its unflipped coordinates, `additionalProperties: false`), `flipX` and `flipY` (`const: true`, as `locked`), appended after `locked` in that order. `x + width ≤ 1` / `y + height ≤ 1` is not a schema rule: `@sododeck/model` trims an overflowing crop on load (contract C2) so the deck still opens. `full.sododeck.json`'s `img-photo` uses all three; invalid fixtures cover each range, a string, a missing key, an extra key, `flipX: false` and `flipY: "yes"`.
