The prototype is a **visual and behavioral reference only**. Never copy its code into `apps/app`: it is a single-file mock (inline styles, hard-coded colors, `localStorage`, CDN React, Google Fonts, Material Symbols) that breaks several constitution rules. We re-implement it with React, Tailwind tokens, shadcn/ui, React Flow and Yjs.

## Re-capturing screenshots

The prototype takes a `screen` prop (`library | editor | flow | rules | empty | export`) and a `theme` prop (`light | dark`) from the `data-props` defaults in `Sododeck.dc.html`. To re-capture: copy `claude-design/` to a temp folder, make one copy of the HTML per screen/theme with those defaults changed, serve the folder over HTTP (`python3 -m http.server`), then drive it with Playwright at 1440×900, `deviceScaleFactor: 2` (states such as focus mode, palette, command palette are reached by clicking/typing, see the file names). Note the prototype loads React from unpkg and fonts from Google, so capture needs network access; this never applies to the real app.

### States 41–85 (`Sododeck State.dc.html`)

`Sododeck State.dc.html` renders one frame from `sododeck-states.js` (`window.SODO_ST.LIST`, states 41–85, sections A flows · B canvas editing · C scale · D library and status). It takes a `state` prop (`"41"`…`"85"`) and a `theme` prop (`light | dark`) from its `data-props` defaults. `Sododeck Extensions.dc.html` is the board that lays those frames out with the design notes (user did / what changed / keyboard / empty-error-motion) and the list of new components and tokens.

To re-capture: same as above, but make one copy of `Sododeck State.dc.html` per state and theme with the two defaults changed, and save `NN-slug-theme.png` using the `id` and `slug` from `LIST`. Wait until `window.SODO_ST` and `window.lucide` exist, then about one second more for the icons to be filled in. The State file also loads lucide from unpkg.

Files fetched through the design preview server carry an injected `<style data-omelette-injected>` + `<script data-omelette-injected>` block after `<head>`; strip it (plus the two newlines that follow) to get the original bytes. The JS files are served unchanged.

### States 86–116 (`Sododeck Canvas State.dc.html`)

`Sododeck Canvas State.dc.html` renders one canvas-first frame from `sododeck-canvas.js` (`window.SODO_CV.LIST`, states 86–116, sections A shell · B card quick-edit · C card colours · D editing affordances). It loads `sododeck-data.js` and `sododeck-states.js` first and takes a `state` prop (`"86"`…`"116"`) and a `theme` prop (`light | dark`) from its `data-props` defaults. `Sododeck Canvas-first.dc.html` is the board with the design notes, the component inventory and the card-colour tokens.

To re-capture: same as for 41–85, one copy of `Sododeck Canvas State.dc.html` per state and theme with the two defaults changed, saved as `NN-slug-theme.png` using the `id` and `slug` from `LIST`. Use a 1440×900 viewport, except **116 at 1024×768** (its `vw` / `vh` in `LIST`), at `deviceScaleFactor: 2`. Wait until `window.SODO_CV` and `window.lucide` exist and `document.fonts.ready` resolves, then about one second more; no `[data-i]` icon placeholder should be left empty.

### Board B rows 117–127 (`Sododeck Cards.dc.html`)

`Sododeck Cards.dc.html` lays out three card-system boards (A Ledger, B Deck, C Spec) with the same 11 rows from `sododeck-cards.js` (`window.SDC.ROWS`: `sample`, `conn`, `groups`, `set`, `edge`, `states`, `zoom`, `fields`, `tags`, `palette`, `types`), plus a comparison. It loads `support.js`, lucide 0.469.0 from unpkg and Geist from Google Fonts. It takes a `boards` prop (`all | A | B | C`) and a `themes` prop (`both | light | dark`) from its `data-props` defaults. Only board B is captured; ids follow the row order (117 `sample` … 127 `types`) and slugs are `deck-` plus the row title (`117-deck-sample-board`, `118-deck-connections`, `119-deck-groups`, `120-deck-sample-set`, `121-deck-edge-cases`, `122-deck-states`, `123-deck-zoom-levels`, `124-deck-typed-fields`, `125-deck-tags`, `126-deck-colour`, `127-deck-type-palette`).

To re-capture: copy `claude-design/` to a temp folder and make one copy of `Sododeck Cards.dc.html` per theme with the defaults changed to `boards: "B"` and `themes: "light"` (or `"dark"`); serve the folder over HTTP and open each copy with Playwright at a 1440×900 viewport, `deviceScaleFactor: 2`. Wait until `window.SDC`, `window.lucide` and 11 `[id^="row-"]` elements exist and `document.fonts.ready` resolves, then about 1.5 s more. In each `#row-<id>`, the plate is the element right after the label whose text is `B · Deck · <theme>`; take an element screenshot of it (1180 wide, natural height: 117 is 900 tall, 120 about 1500).

### Connector rows 128–133 (`Sododeck Cards Connector.dc.html`)

`Sododeck Cards Connector.dc.html` is the same board as `Sododeck Cards.dc.html` with six extra board-B-only rows from `sododeck-cards-connector.js` (the `only: 'B'` rows in `window.SDC.ROWS`). Frames follow 127 and slugs are `connector-` plus the topic: `128-connector-style` (`cstyle`, toolbar and Style popover), `129-connector-bend-points` (`cbend`), `130-connector-label-position` (`clabel`), `131-connector-animated-direction` (`canim`), `132-connector-styles-on-board` (`csample`), `133-connector-style-vs-relationship` (`crules`).

To re-capture: same as board B above (`boards: "B"`, `themes: "light"` / `"dark"`, 1440×900 @2x), but use the Connector file and wait for 17 `[id^="row-"]` elements. Take the element screenshot of the plate labelled `B · Deck · <theme>` in each `#row-<id>` (1180 wide; heights from 875 to 2265).
